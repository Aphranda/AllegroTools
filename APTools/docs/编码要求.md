# 编码要求（会踩，必读）

## 结论表

| 文件类型 | 编码 | 原因 |
|---|---|---|
| `*.il`（SKILL 源码） | **GBK / cp936** | Allegro 在中文 Windows 上按**本地代码页**渲染菜单、对话框、控制台文字。存 UTF-8 会整片乱码 |
| `*.md` | UTF-8 | 编辑器/浏览器的正常约定 |
| `*.ps1` | UTF-8 **带 BOM** | Windows PowerShell 5.1 对无 BOM 文件按 ANSI 读，中文一乱就破坏引号和括号，脚本直接语法崩 |
| `*.py` | UTF-8 | Python 3 默认 |

## 为什么 `.il` 必须 GBK —— 实测依据

1. 用 `(axlUIMenuDump "menu.txt")` 导出菜单；
2. 分别按 GBK 和 UTF-8 读那个 dump。

结果：

| 来源 | 按 GBK 读 | 按 UTF-8 读 |
|---|---|---|
| FanySkill 的菜单项 | `"&切换原点"` ✅ | 乱码 |
| 早期 APTools 的菜单项（UTF-8 文件） | 乱码 | 大部分能看，但**每项末尾字符被吃掉**（`定位孔:` → `定位�`） |

FanySkill 的 `FYEnhanceMenu.ini` 本身就是 GBK（按 GBK 读是 `封装`，按 UTF-8 读是乱码）。
**Allegro 不转换编码，它把字符串按本地代码页直接画出来** —— 文件是什么编码，菜单就按什么编码解释。

所以：UTF-8 的 `.il` 在中文 Windows 上 = 菜单/对话框/控制台中文乱码，而且会**吞字符**。

## 怎么转换

```powershell
# 单个文件: UTF-8 -> GBK
$gbk = [System.Text.Encoding]::GetEncoding(936)
$s = [System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)
[System.IO.File]::WriteAllText($path, $s, $gbk)
```

`devkit\deploy.ps1` 部署前会**自动体检**：发现 `.il` 带 UTF-8 BOM 或不是合法 GBK 就报错并中止
（可用 `-SkipEncodingCheck` 强行继续）。

## 编辑器设置

- **VS Code**：默认 UTF-8，会破坏 `.il`。对这个目录加 `.vscode/settings.json`：
  ```json
  { "files.encoding": "gbk", "[skill]": { "files.encoding": "gbk" } }
  ```
- 或者干脆只在专门的编辑器里改 `.il`，改完**核对编码**再提交。

仓库根有 `.gitattributes` 声明 `*.il` 为 binary 之外的处理方式；编码本身 Git 不校验，
所以**靠人为约定 + deploy 体检**来保证。

## 顺带提醒：`.ps1` 的 BOM

Windows PowerShell 5.1 读无 BOM 的 UTF-8 文件时按 ANSI(cp936) 解释，中文注释里的字节可能
产生 `'` 或 `\` 等字符，**破坏字符串与括号匹配**，表现为莫名其妙的语法错误
（本项目踩了两次）。所有 `.ps1` 一律存 **UTF-8 with BOM**。
