# 待办：SKILL 静态检查器（给 SKILL 补一个"编译器"）

## 为什么要做

写 SKILL 最贵的不是写，是**验证**：一次"进 Allegro 试一下"要十几秒到几十秒，
而且很多错误不会在加载时报出来。2026-09-17 做「电源网络刷色」时，一个几百行的工具
来回了 **8 次** Allegro 启动才跑通，其中 6 次是本可以被静态检查挡住的：

| 实际踩到的 | 现象 | 本该谁抓 |
|---|---|---|
| `substring` 按 0 起算 | `*Error* substring: second argument must not be 0` | 索引 0 的 `substring` 调用 |
| `(255 - a)` 多套一层括号 | `*Error* not a function - (255 - a)` | 单元素括号包单 form |
| `itoa` 不存在 | `undefined function - itoa` | 未定义函数表 |
| `apt_voltAt` 少一个 `)` | 加载**成功**，但后面 4 个过程全被吞掉 | 括号平衡 + 顶层 form 完整性 |
| `apt_netPowRun` 多一个 `)` | `let` 提前闭合，后续语句在载入期执行 → `unbound variable` | 同上 |
| 大整数字面量 | 解析期截断成 `INT_MAX` | 超 `INT_MAX` 字面量 |

结论：**SKILL 缺的是编译期**。现有 `il_check.py` / `il_parens.py` / `il_lint.py` 是
关键词扫描，只能当第一道粗筛。

## 目标

一个 `devkit/il_ast.py`（或直接扩 `il_lint.py`），做到：

```powershell
python devkit\il_lint.py --root APTools core\*.il tools\*\*\*.il
```

输出形如：

```
tools\90_misc\netcolor\APT_NetColor.il:412:5  E  ((255 - a)) 单元素括号包单 form -> 会被当成"调用 255-a"
tools\90_misc\netcolor\APT_NetColor.il:322:44 E  未定义函数 itoa (SKILL 没有 itoa / atoi 是有的)
tools\90_misc\netcolor\APT_NetColor.il:268:25 E  if 实参过多 (最多 3 个: 条件/真/假), 第 4 个是 (when ok ...)
tools\90_misc\netcolor\APT_NetColor.il:124:9  E  substring 的索引实参是字面量 0 (SKILL 是 1 起算)
```

## 设计

### 第一步：词法 + 语法分析成 AST

`il_parens.py` 里已经有半成品（`strip_code` 去注释/字符串、深度扫描）。升级成真解析器：

- 词法：`;` 行注释、`"..."`（含 `\\` 转义）、`(` `)`、`'` 引用、原子（符号/整数/浮点/字符串）
- 语法：递归下降，产出带**行号**的节点。原子记 `kind = symbol|int|float|string`
- 解析失败（括号不平衡/引号未闭合）→ 直接把第 15 条那类坑报出来，并指出**被吞掉的顶层 form**

### 第二步：基于 AST 的检查（按价值排序）

1. **顶层 form 完整性**：每个 `(procedure ...)` 必须在同一层闭合；未闭合的要点名，
   并列出它吞掉了后面哪几个顶层 form（这是最贵的一类 bug）
2. **单元素括号包单 form**：`((x))` → 错（第 14 条）
3. **`if` 实参 > 3**、**`setq` 实参 > 2**、**`when`/`unless` 无 body** → 错。
   `if` 实参过多几乎总是括号错位的**症状**，能反向定位第 15 条
4. **未定义函数**：解析出所有 `(procedure (name ...))` 定义 + 内置白名单 + `axl*` 前缀，
   其余的调用点名。首次运行会有一批误报，把白名单补全即可（`itoa` 这类会稳定被抓）
5. **实参个数**：调用点 vs `procedure` 形参个数（形参表里出现 `.`/可选参时降级为 warning）
6. **前缀/中缀误用**：
   - 前缀形式用了中缀运算符：`(> a b)`、`(+ a b)`、`(/ a b)` …
   - 中缀形式用了函数：`(a mod b)`（`mod` 是函数，第 11 条）
   - 注意 `mod` / `abs` / `remainder` 是**函数**，不要误报
7. **`substring` 索引**：第二个实参是字面量 `0` 或循环变量从 0 起时告警（第 9 条）
8. **超 `INT_MAX` 字面量**：第 10 条
9. **变量未赋值**：文件内读到的全局量，若既没有 `defvar` 也没有 `setq` 也没有在别处定义
   → 告警（能抓拼写错误）
10. **`cons` 第二参不是 list**、**`outfile` 模式参不是字符串**（第 5、6 条）→ 字面量可直接判

### 第三步：接到流程里

- `devkit\deploy.ps1` 部署前跑一遍，**有 E 就中止部署**（现在只做编码体检）
- 加一个 `devkit\checkall.ps1`：一次跑完 core + 所有 tools
- 出个"新工具模板"配套命令，见 `新工具模板.il.txt`

## 落地建议

先做 **1、2、3、8、7** 五条 —— 它们不需要白名单，零误报，而且正好覆盖本轮最贵的坑。
第 4、5 条（未定义函数 / 实参个数）价值最高但需要喂白名单，放第二步。
